# Ranked optimization and reliability backlog

Sequence numbers are intentional. P0 work is a public-release gate; P1 improves performance and maintainability after recovery behavior is executable; P2 is optional or incremental.

| Seq. | Priority | Opportunity and evidence | Expected benefit | Complexity | Regression / security risk | Required tests |
| ---: | :---: | --- | --- | :---: | --- | --- |
| 1 | P0 | **Privileged rollback/recovery harness.** `Netch/Controllers/`, `Netch/Interop/`, `Redirector/`, and `RouteHelper/` mutate routes, DNS, adapters, firewall state, services, and drivers without an automated crash matrix. | Makes cleanup claims measurable and prevents shipping stale host networking state. | High | High; the harness itself performs privileged destructive operations. | Disposable-VM snapshots; fault injection at every start/stop phase; forced host/core/UI kills; reboot and uninstall restoration; multi-NIC, IPv6, offline, unavailable-helper cases. |
| 2 | P0 | **Authenticated broker separation.** `src/Netch.Desktop/src-tauri` remains elevated and the compatibility host inherits that trust. | Removes WebView2 and most desktop code from the administrator boundary. | High | High; weak local authentication would expose privileged networking to another process. | Named-pipe ACL/client identity tests, replay/cross-user rejection, operation allowlist fuzzing, broker upgrade/rollback, UI-without-admin tests. |
| 3 | P0 | **Crash/process supervision with safe recovery.** `EngineSupervisor` detects exit but does not persist a complete mutation journal. Automatic reconnection is intentionally absent. | Clearer unexpected-exit state, reliable cleanup, no orphan helpers, safe manual recovery. | High | High; unsafe reconnect can leak or misroute traffic. | Crash at each transition, orphan detection, idempotent cleanup, journal corruption, repeated recovery, explicit proof that restart never auto-connects. |
| 4 | P1 | **Authenticated runtime-verification cache.** `core/runtime.rs` hashes every immutable packaged file on each preparation; the current manifest is versioned but has no separately authenticated cache record. | Faster warm startup and less disk I/O while preserving integrity. | Medium | Medium/high; a weak cache can bless modified privileged binaries. | Manifest/package authentication, version/length/hash binding, file identity and timestamp attacks, replacement/reparse tests, cache corruption and rollback, cold/warm benchmarks. |
| 5 | P1 | **Deterministic startup parallelism.** Settings load, immutable verification, and non-mutating discovery have independent work, but startup remains deliberately sequential. | Lower cold startup latency on slower disks. | Medium | Medium; ordering mistakes can publish Ready after partial failure. | Fault injection for every future, deterministic first-error policy, cancellation/cleanup tests, repeated cold/warm benchmarks, no overlapping engine starts. |
| 6 | P1 | **Event-driven engine health.** `spawn_health_monitor` performs a serialized status request every three seconds. | Fewer IPC wakeups and faster unexpected-exit notification. | Medium | Medium; dropped events can leave uncertain state. | Event loss/disconnect/reconnect, sequence numbers, heartbeat timeout, concurrent command serialization, CPU/IPC comparison, no automatic tunnel reconnection. |
| 7 | P1 | **Smaller headless compatibility host.** `prepare-engine.ps1` publishes an 84.67 MiB self-contained .NET bridge that still links broad legacy application code. | Smaller installer and lower extraction/start overhead. | High | Medium/high; trimming or separation can break reflection/native/provider behavior. | Publish/trimming compatibility matrix, every provider, settings/modes/import, native loading, single-file extraction, antivirus/signing checks. |
| 8 | P1 | **Provider modernization behind `EngineBackend`.** Inherited provider code and WinForms/global coupling remain in `Netch/Controllers`, `Services`, and `Interop`; the modern runtime intentionally packages only Xray-compatible shapes. | Reduces fragile Rust/.NET boundaries and can restore selected capabilities without frontend churn or unsafe external fallbacks. | High | High networking compatibility risk. | Fixture parity against tag `1.9.7`, protocol/transport matrix, UDP/TCP/DNS, cleanup, explicit fail-closed selection, credential-redaction tests. |
| 9 | P2 | **Optional downloadable geo-routing package.** Geo assets are now intentionally absent because NetF selects applications rather than user domain/IP rules. | Adds domain/IP routing later without restoring about 29 MiB to every install. | Medium | Medium; licensing, authenticity, update, and rule semantics become product surface. | Signed manifest, pinned hashes/licenses, offline behavior, update rollback, geo rule compatibility, DNS leak and route precedence tests. |
| 10 | P2 | **Subscription and batch-link management.** 0.2.0 now provides strict offline single-link import for five supported schemes, but intentionally performs no subscription fetch and accepts no multi-line batch. | Faster bulk onboarding without weakening the typed server authority. | Medium | Medium/high; hostile remote content and secret leakage become direct inputs. | URL/protocol allowlist, response and redirect limits, per-provider parser corpus, duplicate/merge policy, transactional batch import, malicious-input fuzzing, credential-free errors/logs. |
| 11 | P2 | **Further React decomposition and virtualization.** Scanner and Servers are outside `App.tsx`, but `ServerLibrary.tsx` and unusually large imported mode/server lists remain candidates. | Easier maintenance and smoother unusually large libraries. | Low/medium | Low. | Render-count profiling, keyboard/focus behavior, large server/mode fixtures, minimum-size visual tests. |
| 12 | P2 | **Build-cache improvements.** Tauri before-build preparation republishes EngineHost and rebuilds verified native assets even when inputs are unchanged. | Faster developer and CI builds. | Medium | Medium; stale privileged binaries are unacceptable. | Content-addressed input keys, clean-vs-cached byte equality, provenance manifest invalidation, CI cold/warm timings. |
| 13 | P2 | **Structured diagnostics export.** Activity is bounded/redacted but has no single support bundle. | Better incident evidence for startup, state transitions, and cleanup failures. | Medium | Medium/high credential leakage risk. | Golden redaction corpus, hostile logs/settings, size bounds, explicit user consent, archive contents allowlist. |

Recommended next milestone: complete sequence 1 first, then use its fault-injection and recovery evidence to design sequences 2 and 3. Do not parallelize startup or add automatic recovery before the rollback harness can prove the system returns to baseline.
